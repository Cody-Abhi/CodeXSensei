# Accessibility (WCAG 2.2 AA)

PlanPop targets Lighthouse Accessibility 100 and axe-core 0 violations (light + dark, desktop +
mobile). This document holds the manual checklist; automated checks run in Playwright.

## Automated

- axe-core runs on every route via Playwright, in light and dark, desktop and mobile viewports.
- `eslint-plugin-jsx-a11y` enforces accessible JSX at lint time.

## Manual checklist

- [x] Semantic landmarks: one `header`, `nav`, `main`, `footer`; single `h1` per page.
- [x] Logical heading order; no skipped levels.
- [x] Skip-to-content link; visible focus on every interactive element (4px dashed outline).
- [x] Full keyboard operation incl. modals (focus trap), no drag-only actions.
- [x] Form labels always visible; `aria-describedby` for hints/errors; `aria-invalid` on error;
      error summary receives focus on submit.
- [x] AI output region `aria-live="polite"`; loading state `aria-busy`.
- [x] Charts: `role="img"` + `aria-label` summary + visually-hidden data table.
- [x] Touch targets >= 44x44 px; zoom to 200% without loss of content.
- [x] `lang="en"` on `<html>`.
- [x] Status never conveyed by colour alone (icon + text always accompany colour).
- [x] Motion limited to 150 ms transforms; disabled under `prefers-reduced-motion`.
- [x] Contrast >= 4.5:1 for text (black text on all coloured fills).

## Evidence

- axe-core 0 violations across all routes (light/dark, desktop/mobile) — verified in 26 E2E tests.
- eslint-plugin-jsx-a11y: 0 warnings with `--max-warnings=0`.
- ProgressBar uses `role="progressbar"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`.
- Budget chart has `role="img"`, `aria-label` with a summary, and a `visually-hidden` data table.
- Modal uses native `<dialog>` with `showModal()` (browser-managed focus trap).
